## 2. Ce TREBUIE să facă Source (din Knowledge + CLAUDE.md)

### Flow-ul principal promis:
1. User completează formular de sourcing (descriere, tip, zonă, buget, cantitate, urgență, fișiere)
2. AI clarifică cererea (max 3 runde de întrebări)
3. AI generează **Sourcing Package** complet:

- `/dashboard` — Statistici + istoric
- `/api/health` — Health check

### Funcționalități cheie promise:
- AI multi-provider cu fallback (Claude → Gemini → altele)
- Upload fișiere (drag-drop, PDF/DOC/images/DWG)
- Web search real pentru URL-uri produse
- Guardrails validare furnizori (NeMo + local rules)
- Pipeline state machine cu quality scoring
- Autentificare token-based
- Rate limiting per endpoint

## 4. Verificare vs Feedback Utilizator (din memory)

### Feedback #1: "Product URLs never fixed" (23.03.2026)
**Status actual:** PARȚIAL REZOLVAT. Codul are acum 3 strategii (Google CSE → DuckDuckGo → crawl), dar:
- Google CSE necesită `GOOGLE_CSE_API_KEY` + `GOOGLE_CSE_CX` — **nu e clar dacă sunt configurate**
- Fără aceste keys, rămâne DuckDuckGo scraping care e nesigur
- Crawl-ul direct e ultima variantă și adesea returnează homepage
- **Verdictul:** Infrastructura există, dar fără Google CSE keys funcționează slab

### Feedback #2: "Deploy untested — 6+ broken deploys" (23.03.2026)
**Status actual:** NEADRESAT. Zero teste, zero CI/CD, zero health check. Orice deploy rămâne un gamble.

### Feedback #3: "Over-engineering without fixing core problem" (23.03.2026)
**Status actual:** Pipeline state machine, guardrails, quality scoring — toate sunt acolo. Dar problema de bază (URL-uri) depinde de un API key extern. E mai bine decât înainte, dar spiritul feedback-ului rămâne valid: complexitate mare, fundația fragilă.

### Feedback #4: "Background promises lost on PM2 restart"
**Status actual:** NEADRESAT. Nu există job queue, disk persistence, sau recovery mechanism.

### Feedback #5: "Validation too strict for stored data"
**Status actual:** NECLAR — codul de validare din `validation.ts` pare actualizat, dar fără teste e imposibil de confirmat.

## 10. Concluzie

**Source este un MVP funcțional cu AI multi-provider impresionant**, dar are **fundația fragilă** (zero teste, JSON storage, auth opțional). Funcționalitatea core (formular → AI → pachet sourcing) merge, dar calitatea output-ului (în special product URLs) depinde de configurația API keys externe.

### Ce merge bine:
- Flow-ul complet user → AI → rezultate există și funcționează
- Arhitectura codului e curată (lib/ separat, pipeline stages, guardrails)
- AI multi-provider cu fallback e un asset real
- Dashboard-ul oferă vizibilitate

### Ce trebuie rezolvat URGENT:
- **Teste** — fără ele, orice deploy e un gamble (feedback utilizator confirmat)
- **Google CSE keys** — diferența între URL-uri homepage și URL-uri produs reale
- **Auth enforcement** — nu poate fi opțional în producție
- **Upload security** — fișierele nu pot fi publice

### Lecția principală din istoric:
Feedback-ul din 23.03 rămâne actual: **fix-ează problema core (URL-uri, teste, auth) înainte de a adăuga features noi**. Infrastructura adăugată (pipeline, guardrails, quality scoring) e valoroasă, dar nu compensează lipsa fundației.
